# Phase 3: Bass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bass lines that move with energy, vary with the bass seed, lead into each chord with approach notes, never clash with the sounding chord and stay off the kick, plus the riff and call-and-response patterns and an engine refit for pinned bass.

**Architecture:** All work is in the engine (`engine/src/bass.cpp`, `engine/src/validate.cpp`, `engine/src/internal.hpp`, `engine/include/md/types.hpp`).
The plugin, the sub-bass voice and the bass lane already exist and need no change beyond what tests reveal.
Every random draw keeps the rule `Pcg32(<lane seed>, slot)` with fixed slots, so rerolling bass never touches other lanes.

**Tech Stack:** C++20, Catch2, CMake presets `dev`/`asan`/`tsan`/`release`, `scripts/update-golden.sh`, `md-cli`.

**Spec:** `docs/spec/magic-dust-spec.md`: Phase 3, the controls table (energy row), the Bass rules section, validation, and the pins and refit section.
The `docs/DECISIONS.md` rows from 2026-10-26 also bind it: 8 bass patterns, the octave bounce rule, the home chord and pedal, and the in-key rule.

## Global Constraints

- **Range:** the bass range is MIDI 28 to 48, monophonic: no overlapping notes.
- **Pitch:** the current chord's root by default, and patterns may use octaves and 5ths.
- **Approach notes:** at energy above 0.5 (engine energy above 50), add an approach note, a scale step or half step, on the last 16th before a chord change.
- **Kick:** avoid onsets on the four downbeats unless the pattern asks for them.
- **Energy:** low energy means offbeat bass, high energy means rolling bass with approach notes.
- **Reroll:** rerolling the bass never changes the melody's random stream, and other lanes never change bass bytes.
- **Refit:** a pinned bass that would clash is refitted. Pitches snap to the nearest chord or scale tone, the rhythm stays, and the lane carries a refitted flag. The UI badge comes in Phase 5.
- **Validation:** every note is in the key scale or is a chord tone of the chord sounding at its start, in range, with no overlaps.
- **Docs:** no em dash anywhere, and long Markdown has one sentence per line.
- **Commits:** never add Co-Authored-By or an agent name.
- **Before each commit:** dev tests, lint and format pass.

## Definitions this plan fixes

- **Sounding tones:** the pitch classes of the chord lane's voicing sounding at the bass note's start tick. For parallel entries this is the voicing actually heard, as in the existing DECISIONS row.
- **Clash:** a bass note clashes when its pitch class is not a sounding tone and is exactly 1 semitone, in either direction mod 12, from a sounding tone.
  - Chord tones never clash. A root under its own maj7 is fine.
  - The pedal pattern is exempt, because a pedal's whole point is to hold under changing chords.
  - An approach note is exempt. That is a note whose start is the last 16th (swung) before a chord change, and whose pitch is within 2 semitones of a pitch the bass plays at that change.
- **Downbeat onset:** a start on 16th step 0, 4, 8 or 12 of a bar, before swing. Only the sustained pattern may start on step 0. No pattern starts on steps 4, 8 or 12.
- **Density order** (sparse to busy), used by the energy choice: sustained, pedal, offbeat, call-response, garage-skip, octave-bounce, riff, rolling-offbeat.
- **Bass RNG slots:** 0 velocity humanize (unchanged), 1 pattern choice, 2 pitch variation, 3 approach notes, 4 riff motif, 5 call-and-response picks.

## Review Focus

1. **A chord with a half-step-rich voicing:** maj7, min(maj7) or add9 under a riff or call-and-response line must still produce zero clashes. This is covered by the Task 1 property test across all styles, flavours, energies and grooves.
2. **The loop seam:** bar 8 into bar 1 counts as a chord change for approach notes. The approach note must not overlap the next loop's first note when the pattern repeats. Task 3 tests this.
3. **Energy at the boundaries:** energies 0, 50, 51 and 100 must give stable, valid lines. 50 has no approach notes and 51 has them. Task 3 tests this.
4. **An entry listing only one pattern:** the energy choice must still return that pattern. Task 2 tests this.
5. **A reroll changing only bass:** this must hold with the new slots. The existing reroll isolation tests are extended in Task 2.

### Task 2: Energy picks the pattern; the seed varies pitch

**Files:** `engine/src/bass.cpp`, `engine/src/internal.hpp` (the slot constants), `tests/engine/test_generate.cpp`

**Interfaces:**
- Consumes: Task 1's rules, which every generated idea must pass.
- Produces: `BassPattern bassPatternFor(const BankEntry&, int energy, Pcg32& rng)`, which replaces the first-allowed rule.

- [ ] **Step 1:** Write the failing tests.
  - **Low versus high energy:** for an entry allowing offbeat and rolling-offbeat, energy 0 picks offbeat in at least 80% of 200 seeds, and energy 100 picks rolling in at least 80%.
  - **One allowed pattern:** an entry allowing only garage-skip always gets garage-skip.
  - **Riff-only and call-response-only entries:** once Task 4 lands, these return their own pattern. Until then this test uses offbeat entries only.
  - **Reroll:** two bass seeds on the same idea give different bass pitch sequences for at least 90% of 200 seed pairs on rolling-offbeat, and chords and melody bytes stay identical.
  - **Low-variation patterns:** pitch variation never applies to sustained or pedal.
- [ ] **Step 2:** Run them and watch them fail.
- [ ] **Step 3:** Implement the pattern choice.
  - Sort the entry's allowed patterns by the density order. Patterns that are not built yet keep falling back to offbeat until Task 4.
  - With n patterns, pattern k sits at position p = k / (n - 1), and p = 0 when n = 1.
  - Weight each pattern `1 + 4 * max(0, 1 - 2 * |p - energy / 100|)`.
  - Draw with slot 1.
- [ ] **Step 4:** Implement pitch variation with slot 2.
  - The first hit of each chord span is always the root.
  - Other hits on rolling-offbeat, offbeat, garage-skip and call-response choose:
    - root 60%
    - octave 25%: plus 12, or minus 12 when plus 12 would leave the range
    - chord fifth 15%: the chord's actual fifth pitch class, so dim and half-dim chords use b5, placed nearest the root in range

    Out-of-range picks fall back to the root.
  - Octave bounce keeps its existing rule.
- [ ] **Step 5:** Supersede the DECISIONS row "energy does not choose the bass pattern" with a new row stating this rule.
  Update the slot comment in `internal.hpp`.
  Run the full dev suite, lint and format, then commit: `feat(engine): energy chooses the bass pattern and the bass seed varies pitch`.

### Task 3: Approach notes

**Files:** `engine/src/bass.cpp`, `tests/engine/test_generate.cpp`

- [ ] **Step 1:** Write the failing tests.
  - **Energy 51:** every chord change, including the bar 8 to bar 1 seam, has a bass note starting on the last swung 16th before it, for every pattern except sustained and pedal.
  - **Energy 50:** there are no approach notes.
  - **Pitch:** the approach pitch is within 2 semitones of the bass pitch at the change, and the result passes validation.
  - **No overlap:** the note before the approach note is shortened to end at its start.
  - **Loop seam:** the bar 8 approach note ends at the idea's end and doesn't overlap the loop.
- [ ] **Step 2:** Run them and watch them fail.
- [ ] **Step 3:** Implement the approach note, using slot 3. Here the target is the bass pitch at the next change.
  - Choose:
    - from below by a half step, 40%, only when that pitch class is in the key scale (otherwise use the scale step below)
    - from above by a scale step, 30%
    - from below by a scale step, 30%

    Keep it in range, mirroring the direction if it would leave the range.
  - An approach note replaces any hit already on that 16th.
  - It is 1 sixteenth long, velocity 0.85 times the lane base.
- [ ] **Step 4:** Run the full dev suite and the property test, lint and format, then commit: `feat(engine): bass approach notes above half energy`.

### Task 4: Riff and call-and-response

**Files:** `engine/src/bass.cpp`, `tests/engine/test_generate.cpp`

- [ ] **Step 1:** Write the failing tests for each pattern, over 200 seeds and all styles that allow it, plus a forced-pattern test hook if none exists.
  - Every result validates: no clash and no downbeat onsets.
  - Riff: 4 to 6 onsets per 2 bars, with the same rhythm in every 2-bar span.
  - Call-and-response: no bass onset on a 16th where a chord note starts, and 1 to 3 onsets per bar.
  - Entries listing only riff or only call-response now get that pattern, which supersedes that DECISIONS row.
- [ ] **Step 2:** Run them and watch them fail.
- [ ] **Step 3:** Implement the riff, using slot 4.
  - Pick 4 to 6 onsets from 16th steps {1,2,3,5,6,7,9,10,11,13,14,15} of a 2-bar span, with at least 1 step between onsets.
  - Each note lasts until the next onset minus one 16th, between 1 and 3 sixteenths.
  - The first onset of each chord span is the root.
  - Other pitches come from the key scale within plus or minus 7 semitones of the root, rejecting any that would clash.
  - Repeat the rhythm every 2 bars, and re-pick pitches per chord with the same rules and the same draws, so the motif keeps its shape.
- [ ] **Step 4:** Implement call-and-response, using slot 5.
  - Per bar, the candidate steps are the non-downbeat 16ths where no chord note starts, and the step right after a chord note ends is preferred (weight 3, others 1).
  - Pick 1 to 3 per bar. Use more at higher energy: count = 1 + round(2 * energy / 100), capped by the number of candidates.
  - Each note lasts 1 or 2 sixteenths and never runs into the next chord onset.
  - Pitches are root, octave or fifth, as in Task 2.
- [ ] **Step 5:** Run the full suite and the property test, lint and format.
  Add a DECISIONS row superseding the "riff or call-and-response only gets offbeat" row.
  Commit: `feat(engine): riff and call-and-response bass`.

### Task 5: Refit for a pinned bass

**Files:**
- Modify: `engine/include/md/types.hpp` (`Lane::refitted`, default false), `engine/include/md/generate.hpp` or the nearest public header
- Create: `engine/src/refit.cpp`, plus its CMake entry
- Test: `tests/engine/test_refit.cpp`, plus its CMake entry

**Interfaces:**
- Produces: `bool refitBass(Idea& idea)`. It snaps every bass note that fails validation against the current chords to the nearest valid pitch: a chord tone first, then a scale tone, ties going down, staying in range. It never moves a start or a length. It sets `lane.refitted` and returns true when anything changed.
  Pin plumbing and the badge are Phase 5.

  - A valid bass is unchanged and `refitted` stays false.
  - A bass generated against one progression, then given a different chord lane, comes out valid with identical starts and lengths, and `refitted` is true.
  - The refit is deterministic.
- [ ] **Step 2:** Run them and watch them fail.
- [ ] **Step 3:** Implement the refit.
